# Repository Guidelines

Only the `isaacsim` simulator paired with the Hunter robot is in scope for these agent workflows. Keep configs, docs, and code aligned with that combo.

## Project Structure & Module Organization
- `humanoidverse/`: agents, envs, simulator bridges, and shared utils; keep agent-specific logic in subpackages.
- `humanoidverse/config/{exp,robot,rewards,obs,terrain,simulator}`: Hydra YAML overrides; extend via new files instead of editing defaults.
- `assets/` and `humanoidverse/data/robots/`: USD, URDF, STL, and calibration data; document provenance in commit messages.
- `tests/` holds `test_*.py` suites; `docs/` houses contributor guides; `logs/` and `runs/` collect autogenerated outputs.

## Build, Test, and Development Commands
- `conda activate isaaclab`: required Isaac Lab environment with simulator dependencies.
- `python -m pip install -e .`: pick up in-repo changes during development.
- `python humanoidverse/train_agent.py +simulator=isaacsim +exp=locomotion +robot=hunter/hunter +rewards=loco/reward_hunter_locomotion +terrain=terrain_locomotion_plane +obs=loco/leggedloco_obs_singlestep_withlinvel num_envs=16 headless=True`: canonical full training launch; drop to `num_envs=2` for smoke runs when validating the Hunter stack in Isaac Sim.
- `python humanoidverse/eval_agent.py +checkpoint=logs/<project>/<run>/model.pt headless=True`: replay a saved policy offline.

## Coding Style & Naming Conventions
- Target Python 3.8+, 4-space indentation, PEP 8 spacing.
- Use `snake_case` for modules/functions, `CamelCase` for classes, `UPPER_SNAKE_CASE` for constants.
- Prefer absolute imports from `humanoidverse`; add type hints where they clarify interface boundaries.
- Keep comments concise and only for non-obvious logic or simulator quirks.

## Testing Guidelines
- Write tests with `pytest`; filenames must match `test_*.py` for discovery.
- Cover new Hydra configs for the Hunter/Isaac Sim stack with load smoke tests and ensure locomotion heads run with `num_envs=2 headless=True`.
- Run `pytest -q` before pushing; add fixtures or mocks when simulator assets are heavy.

## Commit & Pull Request Guidelines
- Commit messages use present tense and describe intent, e.g., `Add headless locomotion smoke test`.
- Pull requests must outline purpose, Hydra commands, and key metrics or logs when training changes behavior.
- Link issues or experiments, note config default shifts in `docs/` or accompanying YAML, and avoid bundling unrelated tweaks.

## Security & Configuration Tips
- Never commit secrets or large binaries; `logs/` is auto-ignored.
- Prefer Hydra overrides and `.yaml` configs over hard-coded constants so downstream teams can reproduce safely.
- Record new robot asset sources in PR descriptions for review traceability.
